# Git commit message templates.
#
# Read by shell::git::commit::message::base (and so by `shell::git::commit::create --empty`).
# This is DATA, not code: it is parsed on demand and never sourced, so adding a
# template costs nothing at shell start-up.
#
# WHERE IT LIVES
#   This file, in the repository, is the source of truth. install.sh / upgrade.sh
#   copy it to ~/.shell-config/git/git-commit-messages.txt, which is the file the
#   menu reads. After editing it in a clone, run  shell::git::commit::message::sync
#   to refresh that copy. The copy is replaced whenever it differs (the previous
#   one is kept as git-commit-messages.txt.bak), so do not edit it by hand: use
#   your own file, described below.
#
# FORMAT
#   [Category name]                        starts a category (the first menu)
#   :emoji:|type(scope)!|description       one template per line (the second menu)
#
#   - Fields are separated by "|"; blank lines and lines starting with "#" are ignored.
#   - The message is shown as   type(scope)!: :emoji: description   (--plain drops the emoji),
#     so the type stays the prefix and the message is valid Conventional Commits 1.0.0.
#   - emoji       a gitmoji shortcode such as :sparkles:, or empty for none.
#   - type        build chore ci docs feat fix perf refactor revert style test.
#   - (scope)     optional, lower case, e.g. (api) (deps) (ci).
#   - !           optional, marks a breaking change; the description says what breaks.
#   - description starts with a lower-case letter or digit, imperative mood, at least
#                 12 characters, no final period, no quote, $, backtick or backslash
#                 (so it is safe for `git commit -m`). type(scope)!: description must
#                 fit in 72 characters (100 with the emoji).
#   - A template may appear only once.
#
# ADDING TEMPLATES
#   Put a line under the right [Category], or add a new [Category]. Then run
#       shell::git::commit::message::validate
#   which reports every problem with its file and line number. The same format
#   works in your own file, ~/.shell-config/git/git-commit-messages.user.txt,
#   which is read after this one and never overwritten: its categories are
#   appended, and a category with the same name gets your templates added to it.
#   Invalid lines there are skipped with a warning instead of breaking the menu.
